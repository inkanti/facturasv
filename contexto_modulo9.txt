contexto

Estoy desarrollando FacturaSV, un SaaS multiempresa de facturación electrónica para El Salvador.
Los módulos 1 al 9 están completos y probados. La contingencia ya está implementada en modo
simulación; el siguiente trabajo es la integración real con el Ministerio de Hacienda y los tipos
de DTE que aún no tienen esquema.

ENTORNO Y RESTRICCIONES

- Workspace:
  C:\xampp\htdocs\sistemas\factElectronica_saas\facturacion electronica
- Trabajar únicamente dentro de ese directorio.
- Base de datos exclusiva: facturasv2. No utilizar ni modificar otras bases.
- Stack: PHP 8 plano, PDO, MySQL/MariaDB, Bootstrap 5 y jQuery.
- No usar Composer, frameworks ni Node.js para la aplicación.
- No usar subagentes.
- Aplicación compatible con Apache + PHP 8 + MySQL 8 y MariaDB 10.4+.
- URL local:
  http://localhost/sistemas/factElectronica_saas/facturacion%20electronica/
- Acceso demo:

  Contraseña: Demo1234!
- PHP CLI:
  "C:\xampp\php\php.exe"
- MySQL CLI:
  "C:\xampp\mysql\bin\mysql.exe" -u root
- Responder y mantener toda la interfaz en español.
- Trabajamos módulo por módulo; el usuario valida antes de avanzar.

   - No se puede transmitir manualmente un DTE en contingencia sin evento procesado.

REGLAS DTE Y FISCALES IMPORTANTES

- Factura 01: precios con IVA incluido.
- Crédito Fiscal 03: precios sin IVA.
- En ambos resúmenes, la base gravada y el IVA se presentan separados.
- CCF requiere cliente con NIT y correo electrónico; DUI o sin documento no es válido.
- Documentos y teléfonos se transmiten sin guiones.
- Ítems hasta 8 decimales; resumen a 2 decimales.
- El JSON CCF no admite totalIva ni reteRenta.
- rete_renta se conserva únicamente como columna MySQL con valor 0.
- El conector actual es exclusivamente SIMULACION; no existe conexión MH real.
- Departamento y municipio del emisor ya son configurables (módulo 8); valores
  iniciales 06 y 04. El distrito del emisor se guarda por documento.
- Establecimiento demo: M001P001. Zona horaria: America/El_Salvador.
- El número de control depende de empresa + tipo + establecimiento.
- Cambiar el establecimiento crea series nuevas; los documentos anteriores
  conservan su número de control.
- El entorno PRODUCCION está bloqueado en Configuración hasta implementar MHClient.
- El evento de contingencia usa ambiente 00 en simulación y 01 en producción.
- tipoContingencia: 1 MH, 2 emisor, 3 Internet, 4 energía, 5 otro.
- Para el tipo 5 el motivo es obligatorio (máximo 500 caracteres).
- El evento admite como máximo 1000 DTE.
- El evento incluye solo los DTE del tipo de contingencia seleccionado; los demás quedan
  pendientes para otro evento.
- Un DTE solo puede pertenecer a un evento de contingencia.
- El evento y los DTE se transmiten con sellos independientes.

CORREO

- Configuración actual: Mailtrap Sandbox en config/correo.local.php
  (sandbox.smtp.mailtrap.io, puerto 587, TLS).
- Es una bandeja de pruebas: los correos se capturan en Mailtrap y no llegan a los clientes.
- Envío real pendiente: dominio propio verificado en Mailtrap y token de API;
  host live.smtp.mailtrap.io, puerto 587, usuario "api", contraseña = token.
- El plan Sandbox limita correos por segundo; puede responder
  550 Too many emails per second. El sistema lo registra como ERROR.
- No publicar ni compartir config/correo.local.php; está protegido por config/.htaccess.
- Al procesar un evento de contingencia, cada DTE transmitido dispara el correo
  automático del módulo 7; un fallo de correo no revierte el DTE.

PENDIENTES Y SIGUIENTE TRABAJO

1. Integración real con el Ministerio de Hacienda:
   - Implementar MHClient con MHConnectorInterface (firma real, transmisión, consulta,
     invalidación y eventos de contingencia) cuando el usuario entregue endpoints y
     credenciales.
   - El método pendiente es transmitirEventoContingencia(); el mock ya lo implementa.
   - Habilitar el entorno PRODUCCION en Configuración solo después de eso.
2. Tipos DTE 05, 06, 11 y 14:
   - No se generan hasta contar con sus esquemas oficiales.
   - Requieren cálculo, JSON, PDF y pruebas propias.
3. Código QR del DTE:
   - No se incorpora porque la documentación disponible no lo exige para la
     representación gráfica en modo simulación; evaluar con manuales de producción.
4. Envío de correo:
   - El envío es síncrono; evaluar cola/diferido y reintentos con espera para
     límites del proveedor.
   - Configurar dominio y token para envío real a clientes.
5. Contingencia en producción:
   - Validar con el manual técnico el orden exacto de transmisión evento/DTE y las
     reglas de plazo (24 horas) antes de conectar el MH real.
   - Evaluar si el evento rechazado debe permitir editar el periodo o crear uno nuevo.
6. Operación:
   - HTTPS, permisos de escritura solo en uploads/logos/, respaldos, monitoreo.
   - Documentar variables de entorno de producción.
7. Mejoras posibles:
   - Eliminar usuarios (hoy solo se desactivan) con reglas de integridad.
   - Administrar más de un establecimiento desde la interfaz.
   - Filtros adicionales en reportes y dashboard.
   - Notificaciones o auditoría de emisiones.
